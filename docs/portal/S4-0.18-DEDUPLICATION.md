# S4 / Portal 0.18 — Deduplication

Status: **especificação pronta; remoções exigem Runtime/parity**

## Objetivo

Reduzir código custom somente quando Core/contrib/config já cobre a mesma
responsabilidade com paridade demonstrada.

Esta versão não mede sucesso por linhas removidas. Mede por responsabilidades
duplicadas eliminadas sem regressão.

## Regra de remoção

Uma customização só pode sair quando:

1. ownership funcional está identificado;
2. substituto upstream/config está disponível;
3. access/cache/privacy são equivalentes ou melhores;
4. comportamento multidomínio foi preservado;
5. fallback/progressive enhancement foi preservado;
6. teste de paridade passou no Runtime;
7. documentação foi atualizada.

Sem os sete itens, a customização permanece.

## Candidatos

### Breadcrumb

Atual:

`AcultaBreadcrumbBuilder`.

Auditar contra:

- Core breadcrumb;
- base theme;
- Easy Breadcrumb apenas se necessário.

Preservar:

- Domain purpose;
- raízes ACCOUNT/SUPPORT/MAGAZINE/WIKI/COURSES/FORUM quando implementadas;
- rotas ocultas/técnicas;
- titles seguros;
- cacheability.

Não instalar Easy Breadcrumb só para apagar classe custom.

### Schema Metatag plugins

Auditar:

- OrganizationAlternateName;
- OrganizationEmail;
- OrganizationLegalName;
- OrganizationTaxId;
- PostalAddressTag;
- SchemaWebPageName;
- SchemaWebPageUrl.

Para cada plugin:

- existe equivalente upstream atual?
- o schema/property é idêntico?
- config existente migra?
- output JSON-LD/metatag permanece igual?

Remover somente plugin por plugin.

### Menus / Domain links

Auditar:

- preprocess de menus;
- links cross-domain;
- Domain Menu Access candidato;
- URLs environment-aware;
- logout/login/account redirects.

Não trocar lógica de purpose por hostname hardcoded.

### Wiki search antiga

Remover EntityQuery/LIKE **somente depois** do Portal 0.16:

- Search API index PASS;
- Views PASS;
- access PASS;
- acentos PASS;
- URLs WIKI PASS;
- índice lifecycle PASS.

### account-navigation.js

Remover trechos somente depois do 0.15:

- mesma navegação parcial;
- History;
- focus;
- behaviors;
- failure;
- fallback;
- cache/access.

O arquivo pode diminuir por etapas.

### SupportController table

Auditar se Commerce Views/API pode substituir:

- query de orders;
- payments;
- tabela;
- pager/filtros.

Access-first é pré-requisito.

Não trocar por View que exponha orders sem access correto.

### CEP adaptation

`cep-address.js` **não é candidato automático à remoção**.

Preservar enquanto fornecer além do contrib:

- labels ACULTA/PT-BR;
- stale-response protection;
- `aria-live`;
- focus;
- Profile customer integration.

Reduzir apenas o que o `cep_autocomplete` upstream passar a fornecer com
paridade.

### Service locator / static calls

Reduzir `\Drupal::...` quando DI pública é adequada.

Não criar wrappers artificiais só para zerar métrica.

### PortalRequirementsController

Auditar duplicação de:

- Composer requirements;
- Status report;
- module/theme status.

Pode evoluir para providers do Admin Hub ou desaparecer parcialmente.

### Templates/CSS do módulo

Migrar apresentação pública ao design system apenas quando ownership visual
estiver comprovado.

Não mover CSS para o tema se ele ainda pertence a Form API/integration
específica do módulo.

## Processo por candidato

Cada remoção deve ter PR própria ou grupo pequeno coeso:

1. baseline do comportamento;
2. substituto;
3. tests/parity;
4. cutover;
5. remoção;
6. docs;
7. regressão.

Evitar "cleanup PR" com múltiplas áreas.

## Métricas úteis

Registrar por fase:

- classes/functions removidas;
- services removidos;
- CSS/JS removido;
- dependências adicionadas/removidas;
- testes de paridade;
- manutenção transferida para upstream.

Não usar LOC como única métrica.

## Configuração

Quando substituição usa config:

- exportar via Drupal no Runtime;
- não fabricar YAML final manualmente;
- `config:status` CLEAN;
- import test.

## Segurança

Deduplicação não pode remover:

- WebhookGuard Mercado Pago;
- CEP flood;
- Social Auth account-created marker;
- RestrictedTwigStorage;
- wrong-host 404;
- access checks;
- CSRF;
- noindex/private route policy;

sem substituto explícito comprovado.

## Fora do escopo

- reescrever tudo;
- trocar framework;
- instalar módulos só para reduzir custom code;
- remover adaptações de acessibilidade;
- remover fallback sem JS;
- alterar fontes de verdade.

## Gates Runtime

Por candidato, além dos testes próprios:

- PHP/JS lint;
- Drupal container/cache;
- config status;
- Domain matrix;
- User A/B;
- access/cache;
- mobile/a11y quando visual;
- SQLite/MariaDB quando query/config;
- regressão dos subsistemas afetados.
