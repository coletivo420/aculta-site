# S4 / Portal 0.13 — Participation Hub

Status: **especificação pronta; depende de 0.12 Runtime PASS**

## Objetivo

Criar na Minha Conta uma visão integrada das participações do usuário sem
unificar artificialmente as fontes de verdade.

## Fontes

- Fórum: Node + Comment + Forum/Taxonomy;
- Wiki: Node + Revisions;
- Cursos: Group membership + LMS status.

Comment não é uma quarta fonte genérica nesta versão. Respostas do Fórum são
responsabilidade exclusiva do adapter de Fórum. Comentários de outros bundles
não entram no Hub até que exista uma origem/purpose explícitos para eles.

## Arquitetura

```text
Forum adapter ----+
Wiki adapter -----+--> ParticipationAggregator --> presenter --> ACCOUNT
LMS adapter ------+
```

O aggregator não persiste feed paralelo.

## Contrato comum

Cada item pode expor:

- source: forum|wiki|course;
- type;
- title;
- summary/status quando autorizado;
- timestamp relevante;
- URL de navegação environment-aware no purpose correto;
- action opcional;
- cacheability completa da fonte: tags, contexts e max-age, ou cacheable dependency equivalente.

URLs de navegação usam `DomainPurposeManager::routeUrl()`/equivalente
environment-aware para respeitar aliases do Homelab. SEO canonical permanece
responsabilidade separada e não deve ser reutilizado como link de navegação.

Ordenação pode ser feita após agregar listas já autorizadas.

O aggregator deve combinar cacheability completa dos adapters, não apenas
`cache tags`. Se uma fonte exigir `max-age: 0`, `user.node_grants:view`,
Domain ou outro context, essa restrição deve sobreviver até o render final.

## Escopo inicial

- últimos tópicos do usuário;
- últimas respostas;
- últimos verbetes/contribuições Wiki confiáveis;
- cursos ativos/concluídos relevantes;
- links para seções completas.

Não criar feed infinito.

## Design System

Contratos candidatos:

- participation-card;
- activity-list;
- source/status label;
- empty-state.

A origem deve ser semanticamente identificável sem depender de cor apenas.

## AJAX

O Hub pode carregar uma lista inicial no servidor.

Filtros por origem/pager:

- Views AJAX é apropriado para listas filtradas por uma única origem;
- não paginar independentemente cada View e depois mesclar páginas como se
  fossem uma paginação global;
- o Hub combinado inicial deve ser finito e sem paginação global até existir
  contrato explícito de cursor/offset e janela de fetch por adapter;
- se uma paginação combinada for implementada no futuro, ela precisa definir um
  cursor global estável, desempate e quantidade mínima buscada em cada adapter
  para evitar gaps/duplicações;
- evitar endpoint JSON próprio apenas para o Hub;
- HTMX só depois do padrão 0.15 estar validado.

## Access/cache

Cada adapter aplica access antes de retornar item.

O aggregator nunca recebe item proibido para filtrar depois.

Para Wiki baseada em revisão, não basta validar access do node default. O
adapter deve validar o access da revisão/latest-version correspondente e as
permissões de moderação/revisão aplicáveis **antes** de ler título, estado,
timestamp ou URL da contribuição.

Cache deve combinar dependencies completas das fontes e variar por
usuário/permissões, incluindo contexts/max-age específicos de grants/revisões
quando aplicável.

## Gates Runtime

- usuário sem atividade;
- somente Fórum;
- somente Wiki;
- somente Cursos;
- múltiplas fontes;
- conteúdo removido/unpublished;
- User A/B;
- URLs por Domain;
- ordenação;
- cache;
- AJAX/fallback;
- mobile/a11y.

## Fora do escopo

- notifications;
- bookmarks/follows;
- ranking/gamification;
- storage de activity feed;
- analytics comportamental com PII.
